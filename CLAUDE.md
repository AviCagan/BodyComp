## Stop and ask a human before

adding any paid service or API key · adding a native module that forces a new dev build · changing any science
constant in §4.3 · anything touching user photos · switching the 3D rendering approach away from fiber v9 native
without a failed, documented spike. The science in §4 is the spec: do not "improve" it; write an objection ADR
and ask.

## Stack (§3 — decided; relitigate only with a written ADR)

- Expo SDK 57 (React Native 0.86, React 19.2), TypeScript `strict`, `expo-router`, EAS Build + EAS Update.
- State: Zustand for UI/session only. The database is the source of truth.
- DB: `expo-sqlite` + Drizzle ORM. Schema in `src/db/schema.ts`; migrations generated by `drizzle-kit generate`
  into `src/db/migrations` and committed (CI fails if stale); repositories in `src/db/repositories`; tests run the
  same migrations on Node's built-in `node:sqlite` (no native module — see ADR-0019).
- 3D: `@react-three/fiber` **v9 pinned** (`@react-three/fiber/native`) on `expo-gl`; `three` pinned; GLB parsed with
  `three-stdlib`'s `GLTFLoader` from bytes read via `expo-file-system` (never `fetch(file://)`). No fiber v10 /
  `@react-three/native`. Gestures: `react-native-gesture-handler` + `react-native-reanimated` worklets (no
  `OrbitControls`). One component, `MuscleMapView`, with frozen props; WebView is the fallback only after a failed,
  documented device spike.
- Charts: `victory-native` (decide once; ADR if it fights Expo). Backend (Phase 4+): Supabase; the client never
  holds secrets. Video: YouTube Data API v3 via edge function + `react-native-youtube-iframe`. LLM: Anthropic via
  edge function, schema-validated, one retry, then fall back — never produces numbers.
- Testing: Jest (`node` project for engine/data/db/tools; `jest-expo` project for components), RNTL, Maestro
  later. CI: GitHub Actions — `tsc`, `expo lint`, `prettier --check`, migrations up to date, `jest`, GLB validation.
- Exercise seed: `yuhonas/free-exercise-db` (Unlicense) imported by `tools/seed/import-free-exercise-db.ts`.
  Muscle credits come from the literature-derived table `tools/seed/evidence/table.json` (ADR-0023; built from
  `research/`, `verify/` and `corrections.json` by `build-evidence-table.ts`); the name rules are only the fallback.
  `src/data/*.json`, `table.json` and `docs/research/exercise-muscle-evidence.md` are generated — never hand-edit.

## Engine rules (§4.3) — `src/engine/`, pure TypeScript

- No React imports, no `Date.now()`; `now` is injected. 100% unit-tested, including the §8 golden cases.
- Set factors: `hardness` (warm-up 0; RIR unlogged 1.0; RIR ≤ 3 → 1.0; RIR 4 → 0.5; ≥ 5 → 0), `repFactor`
  (< 3 → 0.5, < 5 → 0.75, ≤ 30 → 1.0, > 30 → 0.5), `recency` (≤ 7 d → 1.0, taper to 0 at 10 d),
  `sessionFactor` per group per workout (sets 1–8 → 1.0, 9–12 → 0.5, 13+ → 0.25). Drop sets / myo clusters = one set.
- `effectiveSets(group) = Σ weight × hardness × repFactor × sessionFactor × recency`;
  `frequency` = distinct days in 7 d with ≥ 0.5 credited set.
- `TARGETS` by level (beginner 4/8/12, intermediate 6/12/18, advanced 8/15/22) × `GROUP_MULTIPLIER`
  (delt_front, forearms, traps_upper, erectors, tibialis, neck, hip_flexors 0.5; abs, obliques, adductors 0.75)
  × 1.25 for priority groups; advanced users may override per group.
- Status: 0 → `untrained`; < min → `low`; < target → `partial`; ≥ target → `covered`; > high → flag
  `high_volume`; > 1.3 × high → flag `possibly_excessive`. Color = continuous OKLCH interpolation on
  `effectiveSets / target` (red 0 → yellow 0.5 → green ≥ 1), clamped. Color is never the only signal.
- Regions: share of the group's credited sets via distributions; `under_emphasized` when share < `REGION_MIN_SHARE`
  while the group has ≥ min sets; rendered one step dimmer with a badge and a concrete fix.
- The engine is sex-agnostic; the body choice only selects the rendered asset.
- Other outputs: `recentlyTrained` (≥ 4 sets in 48 h), `distributionAdvice` (≥ 10 sets and frequency 1),
  `overloadStatus` (Epley e1RM, `stalled` after 4 sessions without improvement), `balanceFlags`, `adherence`.
- Constants live in `src/engine/constants.ts` with a cited comment per constant.

## Conventions (§7)

- Layout: `app/` routes (thin) · `src/engine` · `src/db` · `src/features/<feature>` · `src/components` ·
  `src/data` · `src/services` · `src/state` · `src/theme` · `tools/` · `docs/`. Path alias `@/*` → `src/*`.
- Recompute muscle status incrementally on set save; never block the logging UI on it.
- 3D: build the scene graph once; status updates mutate material colors (never re-mount meshes); gesture math on
  the UI thread; no per-frame allocations; `frameloop="demand"`; profile on a real Android device.
- Long lists virtualized. Cold start to a loggable workout < 2 s on a mid-range Android.
- Strings in `src/strings.ts` (English only, i18n-ready). Copy: plain, direct, second person, no hype, no emoji.
  Say "weekly hard sets", "stimulus", "coverage"; never "losing gains", "shock", "muscle confusion", "toning".
  Colors mean programming coverage, not muscle size.
- No analytics or third-party SDKs beyond §3. Accessibility: dynamic type, ≥ 44 pt targets, color + icon + text.
- Weights stored in kg; ids are client UUIDs; timestamps are epoch ms; user-owned rows carry `updatedAt`/`deletedAt`.
- Commits: conventional commits, small and often. Never leave the repo failing `tsc`, lint, or tests.
